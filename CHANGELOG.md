# Change Log

## Unreleased

- **Local Agent Skills (`load_skill`)** — AgentBridge now offers the Agent Skills on this machine the way pi, opencode, and DeepSeek Harness do: a skill is a folder with a `SKILL.md` (YAML frontmatter with `name` and `description`, then instructions) in `.agents/skills` of a workspace folder or in `~/.agents/skills`. Only names and descriptions reach the model up front; the bodies load on demand. An MCP server cannot add to the client's system prompt, so the list goes into the `load_skill` tool description, the one text every client shows the model, and the server instructions tell the model to check it before starting a task. `load_skill` with `name` returns the instructions, the skill directory, and its other files; with `name` and `file` it reads one of those files (text, up to 256 KB, never outside the skill folder, so user skills outside the workspace do not widen `read_files`); without arguments it lists the skills again, including ones added mid-session. Skills are rescanned on every `tools/list`, so a new connection sees new skills. A workspace skill wins over a user skill with the same name; skills with `disable-model-invocation: true` (meant to run only when the user invokes them, as with `/name` in pi and Claude Code) are listed separately, to be loaded only when the user names them; only direct children of a skills folder count. `load_skill` is available in Plan mode. There is no slash-command menu over MCP, so the description tells the model to load a skill the user names (`/deploy`, `$deploy`, "use the deploy skill"). New error codes: `SKILL_NOT_FOUND`, `PATH_OUTSIDE_SKILL`, `FILE_TOO_LARGE`. Refresh cached tool lists (e.g. ChatGPT Connectors) to see the new tool.
- **AGENTS.md loaded automatically** — like pi, opencode, Codex, and DeepSeek Harness, AgentBridge now passes standing instructions from `AGENTS.md` files to the model: `~/.agents/AGENTS.md` first, then, for each workspace folder, every `AGENTS.md` from the enclosing git repository root down to the folder (only the folder itself outside a repository, so an unrelated file higher up the disk is never used). The block goes into the server instructions and, because some clients never show those to the model, also in front of the first tool result of each connection, read afresh at that point. An `AGENTS.md` in a subfolder applies to files under it and is sent once per connection, appended to the first successful `read_files` or `apply_patch` result that touches a file there (the approach of opencode and DeepSeek Harness). Each block is capped at 32 KB like Codex; broader files are dropped before the most specific one is cut off, and the omission is stated. `CLAUDE.md` is not read.
- **AGENTS.md changes reach a running connection** — as in DeepSeek Harness, an `AGENTS.md` that is edited, deleted or emptied, or newly created after it was sent is reported in front of the next tool result: changed and new files with their current text ("replaces the earlier version"), removed ones as "no longer applies". Before, a rule added mid-session reached the model only after a reconnect. The check re-reads a few small files on each tool call. Edits the model makes itself with `apply_patch` are recorded silently instead of being echoed back, and files left out by the 32 KB budget are not resent on every call.
- **Repeated-call reminder** — modeled on DeepSeek Harness's repeat-tool-reminder: when a connection makes the same tool call with identical arguments 3, 5, or 8 times in a row, the result ends with a note asking the model to check whether anything changed and otherwise change its approach or tell the user what is blocking it. The call itself runs normally. An MCP server does not see the user's messages, so any call with a different tool or different arguments resets the count (DeepSeek Harness resets on the next user message); argument key order does not matter, failed calls count, and `get_command_output` on a still-running command is exempt because waiting is a legitimate repeat.
- **Lower memory use for command output and replay buffers** — as in DeepSeek Harness's job output ring, a finished command whose output the model has read now keeps only its last 64 KB instead of up to 2 MB; output the model has not read yet is never dropped by this trim, and earlier offsets report `output_lost=true`. The per-connection MCP replay buffer (used only to resend a response after a dropped stream) is capped at 2 MiB instead of 8 MiB, so 64 idle connections can hold at most 128 MiB instead of 512 MiB. Running commands keep the existing 2 MB window.
- **Panel script and styles in their own files (no behavior change)** — the webview script and styles moved out of the TypeScript template literal in `bridge-panel.ts` into `webview/panel.js` and `webview/panel.css`, inlined at build time by a small esbuild plugin. They get normal editor support and no longer need doubled escapes; `bridge-panel.ts` shrank from 2,461 to 934 lines. The rendered panel HTML is byte-for-byte identical, and `build.mjs` now syntax-checks `panel.js` directly.
- **Server source split (no behavior change)** — `bridge-server.ts` shrank from 3,937 to 3,111 lines: the model-facing text (server instructions, Plan mode guidance and notices, `set_todos`/`report_progress` definitions) moved to `server-instructions.ts`, the panel activity-card parsing to `activity-presentation.ts`, and the HTTP helpers (request body, JSON errors, Origin checks, SSE event store) to `http-helpers.ts`. The moved code is unchanged apart from `export` keywords.
- **Tool descriptions rewritten** — all 14 tool descriptions now follow the layout used by opencode, ZCode, pi, and DeepSeek Harness: one summary line, a blank line, and a few bullets on when to use the tool, key parameters, limits, and how to recover. Implementation details the model does not need are gone (for example the PTY and Shell Integration wording in `run_command`, the 5000-candidate internal bound in `find_files`, and the image re-encoding rules in `read_image_file`), and `apply_patch` now includes an example patch. Every parameter has a description (`command_id`, `input`, `append_newline`, `max_bytes`, the diagnostics `max_results`, and the todo `status` had none), which a new test enforces along with the summary-line layout. Behavior, parameters, and limits are unchanged, and the quoted limits are still generated from the enforcing constants. The descriptions total about a quarter fewer characters. `docs/tool-catalog.md` shows each description verbatim in a text block. Refresh cached tool lists (e.g. ChatGPT Connectors) to see the new text.
- **`apply_patch` can replace a whole file** — `*** Delete File: X` immediately followed by `*** Add File: X` in one patch now replaces the file's content in place instead of failing with "Patch touches X more than once". Before, rewriting a file needed two calls (delete, then add) or an Update hunk that repeated every old line. The replacement is one atomic update: it honors `expected_versions`, keeps the file's line endings and BOM, is rolled back with the rest of a failing patch, and is reported as `action: update` with `replaced: true`. `Add File` on an existing file still fails with `FILE_ALREADY_EXISTS` (Codex silently overwrites here; AgentBridge keeps the guard against accidental overwrites), and that error now explains how to replace the file.
- **`apply_patch` creates missing parent directories** — `*** Add File:` and `*** Move to:` now create missing directories inside the workspace instead of failing. Before, a new file in a folder that did not exist yet failed with a misleading `PATH_OUTSIDE_WORKSPACE: ... has no existing parent directory`, which suggested the path was outside the workspace. The nearest existing ancestor is resolved through symlinks and junctions and must be inside a workspace root, and directories are created one level at a time, so containment checks are unchanged. If the patch fails, the directories it created are removed again. The result lists them in `created_directories`. A file where a directory is needed now reports `NOT_A_DIRECTORY`. In multi-root workspaces a root where the parent already exists is still preferred.
- **`read_image_file` downscales large images** — images whose longer edge exceeds 2000 px, or whose base64 data would exceed 4.5 MB, are resized and re-encoded before they are sent: PNG for PNG/GIF/BMP sources when it fits, otherwise JPEG at quality 80 down to 50, shrinking further only if needed. Before, a 5 MB file became about 6.7 MB of base64, above Anthropic's 5 MB per-image limit, and large screenshots went out at full resolution; in other harnesses an image rejected by the model API stays in the history and breaks every later request. The 5 MB file-size limit is gone; a header check rejects images above 64 megapixels before anything is decoded. Images that already fit are still sent byte-for-byte. The format is now detected from the file bytes instead of the extension, so a JPEG named `.png` is sent as `image/jpeg`. GIF returns its first frame as PNG, BMP is converted to PNG (model APIs do not accept BMP), and JPEG EXIF orientation is applied. The text summary lists the source and sent format, dimensions, and size, plus the scale factor for mapping coordinates back to the source file. New error codes: `IMAGE_DECODE_FAILED` and `IMAGE_PROCESSING_FAILED`. Decoding uses Photon (WebAssembly, Apache-2.0, the library the pi coding agent uses) in a short-lived worker thread, so large images neither block the extension host nor leave WebAssembly memory allocated; the VSIX grows by about 0.7 MB.
- **Plan mode allows read-only commands** — `run_command` is no longer blocked in Plan mode. Each command is checked against an allowlist before it reaches the shell: file inspection and search (PowerShell `Get-Content`, `Select-String`, `Get-ChildItem`, ... and POSIX `cat`, `rg`, `ls`, ...), read-only git (`status`, `log`, `diff`, `show`, `blame`, `grep`, and listing branches, tags, remotes, stashes), and project tests, builds, and type checks (`npm test`, `npm run build`, `npx tsc --noEmit`, and pnpm, yarn, cargo, go, pytest equivalents). The idea follows the plan-mode extension of the pi coding agent but is stricter: every segment of `;`, `|`, `&&`, `||` chains must be allowlisted (pi only checked the start, so `git status; rm -rf src` passed), and redirection other than discarding output (`2>&1`, `2>$null`), command substitution, parentheses, script blocks, `&`, and commands given by path are rejected. Mutating flags of allowlisted tools are rejected too (`find -delete`, `git branch <name>`, `npm audit fix`, `git diff --output`, `sort -o`, ...). A blocked command fails with `READ_ONLY_MODE`, the reason, and the allowed categories. Lint scripts are not allowed because they often fix files. `apply_patch`, `send_command_input`, and `terminate_command` stay blocked.
- **No git pager in managed terminals** — managed terminals now set `GIT_PAGER=cat`. Before, `git log`, `git diff`, or `git show` with more than a screen of output opened a pager that waited for a keypress and kept the terminal busy; in Plan mode the model could not even send `q`.
- **Same tool list in Plan and Build mode** — blocked tools are no longer hidden from `tools/list`; they fail at call time instead. Switching modes therefore never requires a tool-list refresh in the client, which Cloudflare Quick Tunnel could not trigger. `tools/list_changed` is no longer sent or advertised, and the panel notice no longer depends on the tunnel type: "已切换到计划模式：AI 只能读取代码、运行只读命令和测试，修改操作会被拦截。" / "已切换到执行模式：AI 可以修改文件并运行任意命令。"
- **Plan mode prompts modeled on Codex and opencode** — the instructions and notices now say what to do, not only what is blocked: explore before asking, never ask what can be looked up, offer 2-4 options with a recommended default for real preferences, and finish with one complete plan (summary, key changes grouped by behavior, test plan, assumptions) that leaves no decisions to the implementer. A request to make changes during Plan mode is treated as a request to plan them, and Plan mode ends only when the user switches to Build mode in the panel. The switch to Build mode says that all tools and any command are available again. Tool names and the command summary are generated from the enforcing code.

## 0.1.14 (2026-09-24)

- **Foreground `run_command` wait capped at 90 seconds** — the `timeout_ms` default and maximum drop from 120000 to 90000 so a still-running foreground command returns `status=running` and its `command_id` before Cloudflare's 100-second origin response deadline (HTTP 524) can drop the reply. Larger values from clients with a cached tool list are clamped instead of rejected. Refresh cached tool lists (e.g. ChatGPT Connectors) to see the new schema.
- **Unguessable managed-terminal prompt markers** — the per-terminal prompt protocol token now uses `crypto.randomBytes(16)` instead of `Date.now()` + `Math.random()`, so command output cannot feasibly forge completion, exit-code, or cwd markers.
- **Constant-time route-token path matching** — the MCP endpoint and health paths are compared through SHA-256 digests with `timingSafeEqual` instead of plain string equality.
- **Consistent multi-root workspace resolution** — `list_directory`, `get_diagnostics`, `run_command` `cwd`, `lsp`, and Bridge panel resource links now consult every workspace folder in VS Code order, matching the file tools: the first folder containing an entry wins and anything missing everywhere falls back to the first folder. Diagnostics and LSP results from later folders are reported relative to their own folder instead of being dropped. Symlink/junction escape checks are unchanged, and single-folder workspaces behave exactly as before. The resolution logic is shared in `workspace-roots.ts` with dedicated single-root and multi-root regression tests.
- **`set_todos` echoes the full list** — the tool result now keeps the one-line summary and appends the complete validated todo list as JSON (id, title, status), so the authoritative task state appears in the model's transcript as a tool result rather than only as its own call arguments. Clearing reports an explicit empty list. Formatting lives in `todo-format.ts` with dedicated tests.
- **`get_command_output` can wait** — new optional `wait_ms` (0–60000) and `wait_until` (`exit` default, or `output`) parameters block until the command finishes or new output arrives, and otherwise return at the deadline with `wait_result=timeout` while the command keeps running. Results include `wait_result` and `waited_ms` only when a wait was requested, so existing callers see the old shape. Waits are event-driven (no polling), unregister on completion, honor tool-call cancellation, and stay below Cloudflare's 100-second origin deadline. Tool descriptions and server instructions now steer models to one waiting call instead of repeated polling or sleep commands. Refresh cached tool lists (e.g. ChatGPT Connectors) to see the new parameters.
- **Stable error codes on tool failures** — failed results now start with an UPPER_SNAKE_CASE code plus an optional `Hint:` line: `READ_ONLY_MODE`, `UNKNOWN_TOOL`, `NO_WORKSPACE`, `UNKNOWN_COMMAND_ID`, `COMMAND_NOT_RUNNING`, `TERMINALS_BUSY`, `SHELL_UNSUPPORTED`, `INVALID_PATH`, `PATH_OUTSIDE_WORKSPACE`, `INVALID_ARGUMENT`, `CANCELLED`, with `TOOL_FAILED` as the fallback. Existing file-tool codes (`TOO_MANY_FILES`, `STALE_FILE`, ...) pass through unchanged. `set_todos` / `report_progress` validation failures are now returned as tool errors instead of escaping as JSON-RPC protocol errors.
- **Limits stated where the model reads them** — `read_files` (20 files per call), `find_files` (20 patterns) and `set_todos` (24 items) descriptions now state their limits, derived from the enforcing constants.
- **Generated tool catalog** — `docs/tool-catalog.md` is rendered from the live tool definitions by `npm run tool-catalog`. `tests/tool-catalog.test.ts` fails when it is stale, checks every schema is well-formed, verifies that limits quoted in descriptions match the enforced constants (and stay below the Cloudflare deadline), and that both READMEs list the correct tool count and every tool name.
- **Consistent read-only server instructions** — instructions are now built per session from line data. In read-only mode, lines that recommend a blocked tool (apply_patch, run_command, terminate_command, patch/test workflow advice) are omitted or rephrased, and a read-only section right after the intro lists the blocked tools (derived from the enforcing set) and says what to do instead: investigate, present changes as a patch in the reply, and suggest commands for the user. Normal-mode instructions are unchanged byte for byte.
- **Tool list change notifications** — the server now advertises `tools.listChanged` and sends `notifications/tools/list_changed` to every connected session when read-only mode is toggled, so supporting clients drop or restore the blocked tools without a manual refresh. Delivery needs the standalone SSE stream, which stays disabled on Cloudflare Quick Tunnel; there the panel notice now says a manual tool-list refresh is required instead of claiming clients were notified. Clients that miss the notification remain covered by the call-time block.
- **Read-only transition notice in tool results** — each MCP session remembers the read-only state its instructions described. After the user toggles the mode, that session's next tool result (any tool, including a blocked call) starts with a one-time `[AgentBridge notice]` saying read-only mode is now ON or OFF, which tools are affected, and what to do. Tool results are the only per-turn channel an MCP server has, so this reaches clients that ignore `tools/list_changed`, such as ChatGPT. A toggle that ends in the state the session was last told about adds no notice, and sessions are tracked independently.
- **No duplicate read-only log line** — a panel toggle reaches `setReadOnlyMode` twice (the panel handler and the configuration listener); the repeated call with an unchanged value is now a no-op, so the output log shows one `read-only mode enabled/disabled` line per toggle.
- **Plan | Build mode switch in the panel header** — read-only mode is now presented as Plan mode (计划), and normal mode as Build mode (执行). A two-segment switch next to the running/stopped badge replaces both the read-only toggle in Advanced settings and the separate read-only badge: the active side shows the current mode (Build in the button color, Plan in the warning color), and clicking the other side switches. Hovering Plan lists the blocked tools, generated from `READ_ONLY_BLOCKED_TOOL_NAMES`. The post-switch notice appears in the same card under the status line and stays until the next switch (previously it was shown in the address notice, which the next status render hid within about 1.5 s, so it was effectively never seen). The `agentbridge.bridge.readOnlyMode` setting and the model-facing read-only wording are unchanged.
- **Every Bridge start begins in Build mode** — Start (button, persistent auto-start, or command) now turns read-only mode off, in memory and in settings, before the HTTP server comes up, so clients connecting to the new endpoint fetch the full tool list and are less likely to report missing tools later. Automatic tunnel recovery keeps the current mode. The post-switch panel notices are shorter and say what to do: refresh the tool list in the client if the AI reports missing tools (Build), or to hide the blocked tools (Plan).
- **First-call read-only reminder for new sessions** — a session created while read-only mode is active now also gets a one-time `[AgentBridge notice] Read-only mode is ON for this connection…` on its first tool result. Server instructions alone are not reliable here: a client that reconnects mid-conversation (for example after its previous session was closed with DELETE and the user then enabled read-only mode) may never show the new instructions to the model, whose context still shows earlier edits and commands. A toggle before the first call still produces the regular transition notice instead, and sessions created in normal mode are unchanged.
- **No existence probing outside the workspace** — read_files, read_image_file, search_files, find_files, and apply_patch now check containment lexically before touching the filesystem, so any path outside the workspace roots reports `PATH_OUTSIDE_WORKSPACE`, whether it exists or not (previously a missing outside file reported `FILE_NOT_FOUND`, revealing which outside paths exist). Missing paths inside the workspace still report `FILE_NOT_FOUND`.

## 0.1.12 (2026-09-16)

Session headings stay on one line with ellipsis under narrow widths, and cleanup immediately returns refreshed status.
- **Client-neutral temporary-address guidance** — the copied temporary MCP address notice now asks users to update the address in their MCP client instead of naming a specific web client.
- **Expanded lifecycle regression coverage** — deterministic tests now cover Cloudflare Quick, Cloudflare Named, and ngrok startup/recovery; exit/close ordering; stale health responses; Stop/Start concurrency; protocol changes during fallback; explicit HTTP/2 failures without protocol logs; and isolated production VSIX packaging.

## 0.1.10 (2026-09-10)

## 0.1.9 (2026-09-08)

- **New `terminate_command` MCP tool** — the tool surface grows from 13 to 14 tools. A foreground command that outlives its timeout keeps running by design, and a command stuck in a REPL / SSH session never finishes, which permanently occupied its terminal slot (busy slots are never pruned, so every later `run_command` spawned another terminal). `terminate_command` force-kills the managed shell by `command_id` and closes the terminal, freeing the slot; shell state in that terminal (cwd, environment, history) is lost. The call is idempotent for already-finished commands and returns a hard error for unknown ids. Prefer `send_command_input` with `\u0003` (Ctrl+C) first — the `send_command_input` description now documents that Ctrl+C is cooperative and may not terminate REPLs or SSH sessions.
- **Read-only mode also blocks `terminate_command`** — `apply_patch`, `run_command`, `send_command_input`, and `terminate_command` are hidden from `tools/list` and hard-blocked at call time; panel copy, server instructions, and the setting description were updated to list all four.
- **Terminal pool hard cap** — live managed terminals (busy/background included) are capped at 8. When the cap is reached, a command whose cwd matches no idle terminal recycles the least recently used idle one; if every terminal is busy, `run_command` fails fast instead of spawning an unbounded number of terminals. The busy list labels foreground/background commands, shows foreground work first and oldest-first within each class, and warns callers not to terminate intentionally long-lived background tasks.
- **Quadratic output capture removed** — captured `run_command` output is stored as a chunk list with per-chunk offsets: appending no longer re-copies the whole 2 MiB retention buffer on every output chunk, and `get_command_output` locates the requested window by binary search so read cost is bounded by the window (up to 128 KiB) — polling an offset already at the end of the stream returns immediately. `output_lost` / `has_more` / offset semantics are unchanged.
- **Open Terminal activity action fixed** — terminal activity cards now read `terminal_id` from their presentation payload, so `run_command` / `get_command_output` can show the action again. Successfully killed commands do not offer an Open Terminal action for the terminal that was just closed.
- **MCP tool descriptions cleaned up** — `apply_patch` no longer refers to Codex or GPT-family models, image-tool wording is client-neutral and matches the actual base64 file payload, terminal descriptions distinguish cooperative Ctrl+C from a hard stop, and `run_command` now documents the 8-terminal pool limit.
- **Resource bounds tightened** — per-session MCP replay events now have an 8 MiB serialized-payload cap in addition to the 512-event count cap; `search_files` admits at most 16 MiB of source-file bytes into its contextual full-file cache per call; `apply_patch` no longer keeps two full preflight snapshot sets alive at once; and pending MCP initializations count toward the 64-session admission limit.
- **Replay/context edge cases fixed** — expired SSE replay cursors are now rejected cleanly instead of creating a stream that cannot receive future events, and unavailable `search_files` context no longer appears as fabricated blank source lines.
- **Idle UI/resource cleanup improved** — the Bridge panel stops its 1.5-second UI polling while hidden and resumes with an immediate refresh when shown; Quick Tunnel clipboard failures are attempted once per URL instead of retried forever; completed foreground commands clear their timeout handles; `find_files` skips candidates that disappear before `stat`; and stale expanded activity-card ids are pruned with activity history.
- **Quick Tunnel copy status is truthful** — the panel now distinguishes a clipboard attempt from a successful copy. A failed automatic copy no longer leaves the UI claiming success and instead shows a localized warning directing the user to the manual copy button.
- **Quick Tunnel copy ordering hardened** — automatic clipboard writes are serialized and stale completion callbacks are ignored, so a slower copy from an older temporary URL cannot overwrite the clipboard/UI state after a newer Quick Tunnel URL has already been generated; stale failures also no longer show misleading warnings.
- **MCP browser-origin checks tightened** — Streamable HTTP requests without an `Origin` header remain fully compatible with normal server-side MCP clients, while browser-originated requests are accepted only when the Origin hostname matches AgentBridge's known loopback hosts or the current Tunnel domain. Invalid or cross-site origins now receive HTTP 403, and the endpoint no longer advertises wildcard CORS.
- **Workspace symlink boundaries hardened** — `list_directory` and LSP file/project anchors now resolve canonical filesystem targets before reading or opening documents, and workspace-symbol warm-up skips candidates whose real target escapes the workspace. Symlinks that stay inside the workspace continue to work.
- **Command cwd symlink boundary hardened** — an explicit `run_command.cwd` now resolves the real filesystem target before a managed terminal is acquired, so a workspace-local symlink/junction cannot silently place the terminal's initial working directory outside the workspace. This does not sandbox shell commands themselves.
- **Transitive dependency advisories cleared** — the lockfile now resolves `fast-uri` 3.1.7 and `qs` 6.16.0 through the existing MCP SDK dependency tree, clearing the previously reported high/moderate production audit findings without changing AgentBridge's direct dependency surface.
- **MCP route tokens redacted from logs** — Bridge startup (including Persistent Mode auto-start), tunnel recovery, public-health success, health-check failure text, and raw Cloudflare/ngrok child-process stdout/stderr now replace the secret route token with `<redacted>` before it reaches VS Code Output or Cloudflare's internal diagnostic tail buffer. Child-process redaction is stream-safe across arbitrary stdout/stderr chunk boundaries, including tokens with self-overlapping prefixes/suffixes. The full endpoint URL remains available only where it is required for actual MCP requests, panel display, and explicit copy actions.
- **SSE replay eviction race closed** — if a resumable MCP cursor passes the SDK's initial lookup but is evicted before replay begins, AgentBridge now fails that resume request instead of returning an empty stream id that could be registered as a non-functional ghost stream. Normally stale cursors are still rejected by the SDK's existing HTTP 400 pre-check.
- **Tunnel setting ownership clarified** — ngrok and Cloudflare Named Tunnel hostnames are now application-wide user settings, while the Named Tunnel localhost port is machine-scoped and excluded from Settings Sync/workspace overrides. Existing user-level settings keep working, and the existing domain mementos still repair missing user settings; legacy workspace-only overrides are intentionally no longer promoted into the user's global Tunnel identity.
- **ChatGPT Connector refresh required after upgrade** — ChatGPT Connectors caches `tools/list`; after upgrading to 0.1.9, use Settings → Connectors → Refresh (or remove and re-add the Connector) so the cached tool list updates from 13 to 14 tools and exposes `terminate_command`.

## 0.1.8 (2026-09-02)

Tunnel reliability release. The MCP tool surface remains unchanged at 13 tools.

- **Tunnel transport control** — a new `agentbridge.bridge.tunnelProtocol` setting (`auto` / `quic` / `http2`, Cloudflare tunnels only) with a "Tunnel Transport (cloudflared)" radio group in the panel's advanced settings card. `auto` keeps cloudflared's own QUIC-first behavior with the spawned command line byte-identical to previous releases; `http2` forces TCP 7844. The value is re-read on every tunnel spawn, so changes apply on the next start or automatic reconnect without restarting the Bridge.
- **QUIC self-heal with automatic HTTP/2 fallback** — on networks where QUIC handshakes pass but sustained UDP flows die (campus/corporate networks), cloudflared used to blind-retry QUIC until the 60s health check timed out and failed. AgentBridge now watches for repeated edge dial failures with zero registrations: after a 10s grace window it aborts the wait, restarts the tunnel with `--protocol http2`, announces the switch in the panel, and keeps HTTP/2 for automatic reconnects until the next manual start. Explicit quic/http2 choices are never overridden.
- **Honest startup failure diagnostics** — cloudflared process diagnostics now track QUIC dial failures, tunnel registrations, and a rolling log tail. When the health check times out, the error distinguishes "tunnel never registered + QUIC unstable" (a 200-character log tail plus an http2 recommendation) from "registered but unreachable" (the existing ingress hint), instead of always claiming the tunnel connected.
- **Tunnel child lifecycle hardening** — termination is unified in an idempotent `killTunnelProcess` (Windows: taskkill /T /F with a direct-kill fallback, so wrapper-script launches leave no orphaned grandchildren). The QUIC-fallback restart waits for the old process to exit under a 2s bound before spawning, so the startup health check cannot be routed to a dying connector.
- **README known-limitations correction** — replaced the inaccurate "cloudflared falls back to HTTP/2 when UDP is unavailable" claim with the observed behavior (pre-check false positives, unreliable fallback) and documented the new self-heal and the `tunnelProtocol` setting.

## 0.1.6 (2026-08-22)

Reliability release. The MCP tool surface remains unchanged at 13 tools.

- **Fixed scoped file searches with glob patterns** — `find_files` / `search_files` passed an absolute path as ripgrep's search root, but `--glob` patterns match traversal-relative paths, so any search that combined a directory scope with a glob (`src/**/*.ts`, exclude filters) silently returned nothing. Both tools now spawn ripgrep with the scope directory as the working directory and `.` as the root.
- **Fixed `run_command` eating real output lines** — two prompt-stripping passes could remove genuine content: leading lines starting with `$ ` or `PS ...` were dropped from the first captured chunk, and trailing prompt removal could eat real lines when a command's output ended near a prompt boundary. Stripping is now tail-anchored to the end of the output, and the leading pass only trims blank lines.
- **Capped retained finished command states** — long-running Bridges kept every finished `run_command` state forever. States are now pruned to the 32 most recent (running/background commands are never evicted).
- **Honest shell support matrix** — `run_command`'s persistent-shell protocol is now officially supported on PowerShell (Windows), bash (Linux), and zsh (macOS via ZDOTDIR injection). cmd, plain sh, and fish are no longer attempted: selecting one fails fast with a clear error naming the supported shells, instead of hanging ~8 s waiting for protocol markers that never arrive.
- **Layered DoH hardening for Quick Tunnel health checks** — on networks whose DNS cannot resolve `*.trycloudflare.com` subdomains (campus/corporate resolvers), startup no longer times out after 60 s. Cloudflare's own DoH endpoint is tried first (zero propagation lag for its own zone), DoH queries carry a cache-buster with `no-store`, and if every resolver fails — including the window where the account-less control plane has not yet published its DNS record — the health check falls back to pinned Cloudflare anycast IPs with SNI + Host headers while TLS stays validated against the real hostname. A new `[bridge] DoH fallback exhausted, ...` log line makes the fallback path visible in the Output panel. First successful starts on affected networks drop from ~60 s to a few seconds.
- **Housekeeping** — file locks now use reference counting so idle mutexes are evicted; removed a misleading empty authorization hook from the Bridge start path.
