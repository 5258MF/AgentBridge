# AgentBridge regression tests

Run the complete suite with `npm test`. The runner first type-checks the test TypeScript, bundles the tests into a random system temporary directory with the repository's existing esbuild dependency, and executes them with `node:test`. On Windows it then copies the current workspace state (including uncommitted changes) to a second random system temporary directory while excluding `.git`, `node_modules`, the existing `dist`, VSIX files, and temporary artifacts; the copy reuses the workspace's already-installed dependencies through a local junction, runs the existing `build.mjs` there, packages that freshly built copy with the locally installed pinned `@vscode/vsce` binary, and inspects its ZIP contents. It does not run an install step or overwrite the workspace `dist`. Temporary test bundles, workspace copies, and VSIX files are removed in `finally` cleanup paths.

The tests exercise real production code rather than copied test implementations. `origin.test.ts` imports the production `normalizeTrustedBrowserOrigin()` function. `trusted-origins-panel.test.ts` instantiates the production `BridgePanelProvider`, executes the inline JavaScript from the actual rendered Webview HTML in `node:vm`, drives real `input`, `click`, and `message` handlers, and separately exercises the production Host save handler. `session-management.test.ts` drives the real session status snapshot, Webview classification, public-health presentation and request-ID-scoped manual-check completion (including failure and stale completion), host-side idle-session cleanup, stale-UI request/SSE race protection, late MCP initialization rejection during teardown, and immediate refreshed status response. `terminal-lifecycle.test.ts` covers managed-PTY hard-stop idempotency, stale exit callbacks, old-slot retirement and fresh-terminal creation after termination, plus natural PTY exit completion. `bridge-start-command.test.ts` activates the real extension command registration and verifies cancellation handling, ordinary error propagation, and that deactivation prevents delayed Persistent Mode auto-start. `tunnel-lifecycle.test.ts` instantiates the production `BridgeManager`, drives its real start/stop/recovery paths for Cloudflare Quick, Cloudflare Named, ngrok, and development local smoke, enters automatic recovery through fake process and controlled timer events, and verifies QUIC-to-HTTP/2 fallback, exit/close log-drain ordering, pre-listen HTTP shutdown, serialized failed-start/Stop teardown, abortable tunnel checks, cancellable recovery backoff, hard monitor deadlines with ignored late success, stale health and Quick URL isolation, Stop→Start health-monitor isolation, ngrok manual-only monitoring, hanging response-body cleanup, request/response HTTPS destruction and failures, DoH global-IPv4 and generation-cache boundaries, close-only recovery, startup process-error cancellation, bounded old-process shutdown, explicit protocol precedence, immediate restart after a cancelled start, and continuous public-health fluctuation/outage/recovery state.

Only runtime boundaries are replaced in the test build: a minimal VS Code API fake, controllable child processes, fake local HTTP/direct HTTPS transports, controlled timers, and controlled public-health `fetch` responses. Those substitutes make race ordering deterministic without real installers, external network calls, or long sleeps. They do not replace the trusted-origin normalization, Webview state machine, Host save logic, Bridge lifecycle generation/cancellation guards, health-monitor scheduler, or recovery loop under test.

The Windows package validation is intentionally Windows-only because this release workflow only guarantees full Windows acceptance. On another platform it is skipped with a message and the core regression tests still pass; `npm test -- --require-package` is the explicit opt-in for failing there instead, and `npm test -- --skip-package` runs only the core regression tests. The package test derives the VSIX entry prefix from the actual ZIP, requires the production manifest, freshly built bundle, icon, runtime ripgrep binary, localization files, READMEs, and changelog, and rejects `tests/**`, test-build artifacts, mutation artifacts, and temporary test configuration.

These tests are regression coverage, not an installation or end-to-end service environment. Fake VS Code/process/network behavior does not replace testing installation in a real VS Code Extension Host, cross-platform installation, or live Cloudflare/ngrok connectivity.

For one-off mutation acceptance, `node tests/run-tests.mjs --match origin --skip-package`, `--match trusted-origins-panel`, or `--match tunnel-lifecycle` can run an isolated subset. Mutation checks are not part of daily `npm test`; perform them only in a copied temporary repository and delete the copy afterward.
